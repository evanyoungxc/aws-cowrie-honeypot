# AWS Cowrie Honeypot

A public-facing SSH honeypot deployed on AWS EC2 using Cowrie to capture, monitor, and analyze real-world malicious activity.

This project started as a way for me to gain hands-on experience with honeypots and Linux security monitoring. I deployed Cowrie to the public internet and have used the activity it captures to analyze credential attacks, automated reconnaissance, command execution, malware deployment, and other SSH activity.

![Cowrie Honeypot Dashboard](images/dashboard.png)

## Live Dashboard

**Live Dashboard:** http://54.210.18.142/index.html

I built a live monitoring dashboard to make activity captured by the honeypot easier to view and analyze.

Cowrie JSON logs are processed by a Python script into sanitized telemetry that is served through Nginx. A systemd timer regenerates the dashboard data automatically, while the frontend checks for updated data every 30 seconds.

The dashboard currently displays:

- Total SSH connections
- Unique source IPs
- Successful login attempts
- Failed login attempts
- Commands captured
- File transfer events
- Daily SSH connection activity
- Daily successful login activity
- Recent connections
- Top source IPs
- Top usernames
- Top HASSH fingerprints
- Recent commands
- Top commands

Raw logs, captured credentials, transferred payloads, private keys, and administrative SSH access are not exposed through the dashboard.

## Architecture

```text
                    Internet
                       |
                       v
                 AWS EC2 Instance
                       |
              Public TCP Port 22
                       |
                       v
                iptables Redirect
                       |
                       v
                Cowrie SSH :2222
                       |
                       v
                 Cowrie JSON Logs
                       |
                       v
                 Python Processing
                       |
                       v
                Sanitized data.json
                       |
                       v
                 Nginx Web Server
                       |
                       v
                 Live Dashboard
```

The honeypot runs on an Ubuntu EC2 instance in AWS.

Public SSH traffic sent to port 22 is redirected to Cowrie running as an unprivileged service on port 2222. Real administrative SSH is separated from the honeypot and runs on a different restricted management port.

The dashboard is served through Nginx and receives only the sanitized JSON output generated by the dashboard parser.

## Honeypot Monitoring

Cowrie records events such as:

- Incoming SSH connections
- Source IP addresses
- Authentication attempts
- Usernames and passwords attempted
- Successful Cowrie authentications
- Commands executed inside honeypot sessions
- SSH client fingerprints
- File uploads and downloads
- Session activity

Cowrie's JSON logs allow the activity to be analyzed without relying only on the interactive Cowrie log.

## Log Analysis

I created Python scripts to process Cowrie's JSON logs and summarize activity across current and rotated log files.

The analysis includes:

- Connection counts
- Unique source IPs
- Successful and failed authentication attempts
- Most common usernames
- Most common commands
- HASSH fingerprints
- File transfer events
- Individual session activity

Session-level analysis makes it easier to separate simple internet scanning from attackers that successfully authenticate and begin interacting with the honeypot.

## Captured Activity

Since being exposed to the public internet, the honeypot has captured several types of activity, including:

- Automated SSH scanning
- Credential attacks
- Post-authentication system reconnaissance
- Automated command execution
- File transfers
- Malware deployment attempts
- Cryptomining-related activity
- SSH worm activity
- SSH tunneling and proxy attempts

Notable activity is documented in the `analysis/` directory.

## Malware Analysis

When Cowrie captures a transferred file, I do not execute the payload.

Captured files are investigated using techniques such as:

- SHA-256 hashing
- File type identification
- Static string analysis
- Cowrie event correlation
- Session analysis
- VirusTotal results when appropriate

This allows suspicious files to be investigated without intentionally executing malware on the system.

## Security Considerations

Because the honeypot is intentionally exposed to untrusted internet traffic, I separated the honeypot service from administrative access.

Some of the security measures used include:

- Cowrie runs as an unprivileged user
- Public SSH traffic is redirected to Cowrie
- Administrative SSH uses a separate port
- Administrative SSH access is restricted by AWS Security Group rules
- Raw Cowrie logs are not exposed through Nginx
- Captured credentials are not published on the dashboard
- Captured payloads are not publicly hosted
- SSH private keys are not stored in the repository
- Dashboard data is sanitized before being served publicly
